# Deep dive 2026-11-19: index latency, mail-lane errors, engine shootout

Public-safe summary of a full audit of one 24 GB M4 seat. No work content is included.

## Fixes

| Problem | Root cause | Fix | Result |
|---|---|---|---|
| Sentinel red, "mail has not updated" | The mail bridge exits 3 with plain text `owa bridge busy` on a lock timeout; the indexer only recognized a JSON busy payload, so lock contention counted as an error | Treat plain-text busy as a deferral; error lines carry the first stdout line with long tokens redacted | Green; mail lane ingests every ~30 min |
| Vector channel quietly degraded | The query server ran under a system Python without numpy / sqlite-vec and fell back to scanning only the newest ~8k rows | Server adds the project venv's site-packages to `sys.path` | Full index searched again |
| Vector lookup 2–6 s | Brute-force vec0 scan of ~900k × 384 float32 (~1.4 GB) paging under memory pressure | `hailports/brain/vec_binary.py`: 1-bit sign sketch (~43 MB) + source mask before candidate pick + exact cosine rescore; kill switch `HAILPORTS_VEC_BINARY=0`, any error falls back to the exact scan | 0.18–0.5 s, recall@10 0.94–0.96 vs exact; in-scope similarity higher than the old post-filtered exact path |
| Graph-hit hydrate ~0.8 s each | Full scan of the docs table | Join through the (source, ref) → rowid map | Milliseconds |
| Duplicate hits | Same doc via hybrid and graph | Dedupe by (source, normalized title) | — |

End-to-end ask latency on five real lookups: mean 7.28 s → ~1.03 s.

Note on bit order: sqlite-vec's `vec_quantize_binary` packs dimension 8j+i into bit i of byte j
(LSB first). numpy needs `packbits(..., bitorder="little")`, or recall is zero.

## Engine shootout (one model at a time; two ~14 GB models OOM the GPU on 24 GB)

16 work-style prompts, temperature 0, thinking off, identical retrieved context; 0–2 usefulness score each.

| | MiniCPM-V-4.7-35B-A3B IQ3_XS, llama.cpp + dspark | Qwen3.6-35B-A3B UD-Q2_K_XL, Splash + DFlash2 | Qwen3.6-35B-A3B UD-IQ3_S, Splash + DFlash2 |
|---|---|---|---|
| Usefulness / 32 | 25.5 | 26.5 | 25.0 |
| Decode tok/s mean | 46.1 | 87.0 | 79.3 |
| Prompt tok/s (~1.5–2k ctx) | 386 | 577 | 579 |
| TTFT short / with context | 0.45 / 3.93 s | 0.28 / 2.64 s | 0.27 / 2.63 s |
| Vision | yes | no (`--language-only`) | no |

Quality tie, Splash Q2_K_XL about 1.9× faster decode. The IQ3_S quant is slower with no quality gain.
Before switching a seat: confirm nothing needs vision, check `/health` / `/metrics` consumers, and run a shadow period.

## Scripts

- `scripts/sandbox_llama.sh` — guarded side-port server; refuses protected ports; kills on low memory level or swap growth.
- `scripts/ab_window.sh` — hold the live model with its pause flag, run candidates one at a time, always restore and log argv + health.
- `scripts/weekly_sweep.sh` — read-only weekly report: launchd exits, health URLs, memory/swap, per-source freshness, decode probe.

## Cutover to Splash (same day)

The Splash build went live on port 18080 after the vision and file checks passed on both models. Total planned downtime was about 5 minutes (weights had to be copied to the internal volume first), plus two short engine restarts (about 30 s for an over-size test prompt, 24 s to apply the 65536 cap). Details, measurements and the shim/trimmer design are in `MODEL.md`. The previous model, its serve script and its draft stay on disk only as the rollback target; the Splash path does not use a separate draft server.
